R relevent effect coverage

Relevent fits exact full-risk-set maximum likelihood for ordinal order and exponential interval timing with statistics constant between events. Finite half-life timing statistics are rejected; see Timing Models. It implements a subset of R relevent::rem.dyad; rem_dyad === fit_relevent is a Julia function alias, not an R argument adapter. R's default fit.method="BPM" includes a prior; Julia's OrdinalBPM uses maximum likelihood despite the historical type name. For a comparison, request R's MLE.

The six normalized degree effects start at 1/(n-1) before the first event, as in R relevent 1.2.1. An unseen recency partner has value zero. Recency ranks use event order, not elapsed time. The two-path/shared-partner effects use cumulative counts with the minimum along each path; replacing counts by binary adjacency or products changes these statistics.

using REM, Relevent
n = 4
history = InteractionHistory()
update_history!(history, Event(1, 2, 1.0))
update_history!(history, Event(2, 3, 2.0))
compute(OTPSnd(n), history, 1, 3, 3.0) # 1.0
compute(RSndSnd(n), history, 1, 2, 3.0) # 1.0
stats = [NIDSnd(n), RRecSnd(n), OTPSnd(n), CovSnd([-1., 0., 0.5, 1.])]

All these statistics support compute(stat, history, sender, receiver, time) and compute(stat, REM_state, sender, receiver). The cumulative catalogue statistics read the retained event log: every row counts once, regardless of an REM state's weights, decay, or window. They require keep_history=true; REM's fitting pipeline enables this through needs_history. To model decayed counts, use Relevent's PriorInteraction, SendingCapacity, ReceivingCapacity, LocalInertia, or Momentum. For REM's weighted/windowed/eventnet statistics, use its own statistic types. The distinction is part of the model specification.

Validation and remaining limits

test/fixtures/relevent_catalogue.toml, generated by the checked-in R script, compares 24 individual design columns from 15 constructors on all 20 candidate dyads before each of 14 events, including an isolated actor and repeated dyads. R's rem.dyad.lambda returns log rates: setting one coefficient to one and the rest to zero exposes the corresponding statistic. This deterministic fixture uses tolerance 1e-12. The separate relevent_rem_dyad.toml retains the fitted coefficient, baseline uncertainty, standard-error and likelihood comparison at 1e-6; it covers CovSnd, CovRec and four participation shifts. The design fixture does not establish fitted-coefficient parity for every combination of effects.

The following remain unsupported:

  • FrPSndSnd, FrRecSnd, and OSPSnd. A probe against installed R relevent 1.2.1 found results that differ from the descriptions of these effects. After one 1→2 event, FrPSndSnd gives zero on 1→2 rather than the described fraction one. On a longer repeated-dyad sequence, OSPSnd gives asymmetric outgoing shared-partner values. The matching source's lambda_R passes the whole accumulated interaction list to logrm_normint, whose comment requests one iteration; acl_tri_R's reverse shared-partner update addresses the same list entries as its forward update. These reproducible discrepancies require reference clarification before Julia claims parity; no substitute is exported.
  • Event-indexed arrays for CovSnd, CovRec, CovInt, and CovEvent. Static covariates and one Julia statistic per covariate column are supported.
  • Bayesian posterior mode, BSIR, prior controls, R GOF/residuals and simulation, conditioned.obs, and restricted/changing risk sets.
  • Group-directed or self-directed fitting. PShift can evaluate null-actor transitions, but the fitters' risk set is every directed non-self dyad among actors 1:n; it excludes receiver zero.
  • Weibull/Gompertz parameter estimation. Their hazard/survival evaluators exist; interval fitting estimates only an exponential baseline.

The probe supporting the three deferred effects can be repeated with Rscript test/fixtures/r/relevent_deferred_probe.R. R source used for inspection: CRAN relevent source.
